# 0.2.4 — исправление длинных путей и merge

## Область

WR-028-01 и WR-028-02 из отчёта 028 подтверждались и в 0.2.3, несмотря на
97 успешных штатных тестов. Ранее исправленные `0555`, корневой mode и `0000`
не были исправлением этих двух дефектов.

## Что изменено

Архиватор пишет POSIX PAX `path`/`linkpath` при длинных или многобайтовых именах.
Длина записи считается в байтах UTF-8, а не в символах. Поддержаны длинное имя
105 байт, точный ERP-путь 237 байт из отчёта, UTF-8 пути, переводы строк и `=`
в именах, длинные цели внутренних символических ссылок. Никакого усечения и
автоматического исключения обязательных файлов нет. Независимый GNU tar читает
наши архивы; наш reader читает GNU PAX (44 записи сверены в обоих направлениях).

В merge каждый существующий компонент назначения проверяется без следования
символическим ссылкам. На Linux операции привязаны к дескрипторам каталогов
через `/proc/self/fd`. File writes создают отдельный файл и затем атомарно
заменяют конечную запись. Ни данные, ни mode внешнего hardlink alias не меняются.
Уже существующая ссылка на место обычного файла отвергается, а идентичная
внутренняя архивная ссылка может быть сохранена. Обычное слияние не отключено.

Сам reader проверяет checksum заголовка, точные числовые поля, PAX byte lengths,
размеры, типы записей, дубликаты нормализованных имён, два завершающих нулевых
блока и нулевой хвост. Повреждённый архив не объявляется восстановленным.
Допустимы file/directory/internal symlink; sparse, special files и неизвестные
PAX-атрибуты не интерпретируются молча. Лимит метаданных одного PAX — 1 MiB.

Промежуточный TAR хранится в случайном приватном подкаталоге `os.tmpdir()`,
а не по предсказуемому имени в общей временной папке. Pipeline обрабатывает
ошибки чтения, записи и сжатия. Частичные writes дописываются до конца.
Output внутри source и уже существующий output не перезаписываются. Изменение
наблюдаемых файлов/каталогов во время capture приводит к явной ошибке.

## Чистая комната

`createCleanRoom` вызывает `mkdtemp(path.join(os.tmpdir(), ...))`. На проверенном
Linux без override это `/tmp`. Регрессия проверяет отдельный `TMPDIR` и удаление
только созданной комнаты. Комната удаляется только после полного успешного
rehearsal. При warning/ошибке она сохраняется с путём в receipt.

При cleanup chmod привязан к открытому дескриптору, не к повторно разрешаемому
имени. Linux O_PATH позволяет владельцу безопасно открыть даже каталог `0000`,
вернуть owner-rwx через ссылку на этот дескриптор и удалить свою комнату. Это
не изменение test workflow и не очистка каталога реального restore.

## Проверки и пределы

Полный текущий набор: 129 тестов, включая все прежние 97; проверяется также
непривилегированным UID. Основной RED — 16 из 20 новых проверок на старом коде;
отдельно сохранены RED для cleanup race и `0000`. Первый CLI probe ошибочно
передавал `backup --manifest`; он не считается доказательством регрессии.
Исправленный probe использует документированный позиционный manifest и повторён
на неизменённой 0.2.3. Старые утверждения не удалялись и не ослаблялись.

Для точного ERP-пути использованы тестовые байты. Полная рабочая область ERP,
оригинальный PNG и 84 896 записей из чужого окружения не объявляются проверенными.

Реальный target и его предки должны быть под исключительным контролем оператора.
Дескрипторы защищают от перенаправления операции через symlink, но инструмент не
является sandbox против процесса с теми же правами, способного переместить весь
уже открытый каталог наружу. Bind mounts и действия привилегированного противника
также вне этой гарантии. Не запускайте merge параллельно с изменением target.

Linux требует доступный `/proc/self/fd`. Другие ОС отдельно не сертифицированы.
Сохраняются пути, file bytes, обычные Unix mode и внутренние ссылки. UID/GID,
ACL/xattr, sparse layout, hardlink topology и все timestamps не являются обещанием
этого формата. Невалидные UTF-8 имена явно отклоняются, не переименовываются.
Snapshot работающей БД/атомарность нескольких файлов остаются задачей объявленного
автором workflow: наблюдение metadata не заменяет согласованный DB snapshot.

JSON-семейство остаётся текущим v2. Новые handoff-manifests требуют `pax-paths`
и `safe-merge`: старый исполнитель должен отклонить неподдержанные capabilities,
а не пытаться восстановить копию с утратой имён или прежней уязвимостью.
