# Интеграции среды: один процесс, без ручных пауз оператора

Формат документов: **v3**, выпуск 0.3.0. Существующие v2-сессии читаются своим
выпуском 0.2.x; автоматического преобразования нет.

## Граница возможностей

Инструменты Google Drive/Gmail доступны агенту, но не обязательно процессу Node.
CLI не извлекает токены интеграций и не обращается к вымышленному api_tool endpoint.
Host bridge связывает два исполнителя: CLI определяет операции, агент вызывает
разрешённые интеграции и возвращает результаты. Участия оператора между ними нет.

При программируемом host его собственный dispatcher можно объявить в локальном
`capabilities.json` как `dispatchCommand: ["/path/to/dispatcher"]`. CLI передаст
два аргумента: путь request и путь ожидаемого results. Команда запускается без
shell. Dispatcher не входит в резервируемое приложение и использует только
собственную авторизацию host. File bridge не является security sandbox против
процесса с тем же UID; каталог должен быть под контролем оператора.

## Готовые формы

Скопировать `templates/connector/capabilities.example.json`, указать реальный
аккаунт и только действительно доступные операции. Не отмечать возможность
отправки, если интеграция доступна лишь на чтение. Реквизитов OAuth в форме нет.

```bash
workspace-recover bridge init --bridge /work/bridge --capabilities capabilities.json
workspace-recover backup manifest.json --executor connector --bridge /work/bridge
```

Агент, пока процесс работает, получает **весь пакет**:

```bash
workspace-recover bridge pending --bridge /work/bridge --json
workspace-recover bridge submit --bridge /work/bridge --results results.json
```

Оператору не нужно делать эти вызовы. Их выполняет агент или host dispatcher.
`connector` ждёт результаты внутри того же процесса; `delegated` сохраняет
ожидание и выходит, после чего агент продолжает ту же сессию через `continue`.
`direct` использует собственный OAuth; `auto` выбирает зарегистрированный полный
connector либо подготовленный direct-профиль. Выбор фиксируется в отдельном
executor plan данной сессии. Потеря канала не переключает аккаунт или executor.

## Отображение семантических операций на инструменты host

| Операция | Действия агента | Что вернуть |
|---|---|---|
| `drive.upload` | Загрузить exact artifact в folderId; не менять sharing | id, url, parent, bytes |
| `drive.download` | Получить metadata и заново скачать exact id | id, parent/parents, path к полученным байтам, bytes |
| `drive.metadata` | Прочитать exact id | id, parent/parents, bytes |
| `gmail.send` | Передать точные to, subject, bodyFile, JSON-вложения | id сообщения и url |
| `gmail.read` | Прочитать сообщение, скачать перечисленные JSON-вложения | id, subject, to[], body, attachments[] с name/path |

Названия реальных connector-функций определяет текущая среда, а не recovery core.
Файловые ссылки host при необходимости материализуются его штатным механизмом.
Ответы содержат реальные пути полученных файлов, не base64 и не access tokens.

Каждый ответ привязан к requestId, requestHash и sessionId. Повтор того же ответа
не повторяет операцию. Конфликтующий ответ не заменяет принятый. Для утерянного
результата отправки передать status `unknown`: письмо не будет автоматически
отправлено повторно. После чтения remote-состояния передать результат с
`resolvesSha256`, указывающим SHA256 канонического предыдущего response. История
не стирается; разрешение хранится отдельно. Таймаут оставляет request для
продолжения. Текущие форматы и неизменность SHA не доказывают авторизацию host:
данные интеграции отмечаются как host attestation; полученные байты проверяются CLI.

## Завершение

Копия публикуется, скачивается, проверяется и восстанавливается по точному внешнему
manifest в OS-temp комнате. После этого manifest сохраняется отдельно и также
скачивается. Письмо формируется из полученных ссылок, отправляется и перечитывается.
Проверяются body, recipients, subject и SHA256 всех вложений. Readback не является
обещанием отсутствия последующего bounce. Исполняемый архив в Gmail не прикладывается.

Собственные тесты/cleanup выполняются только в порядке manifest. Частичная
распаковка и прерванная команда не запускаются повторно вслепую. `info --type
connector --view full` возвращает только путь к полным сохранённым обменам.

Профиль доступа не включается в recovery semantics: Google IDs и folder boundary
сохраняются, но получатель вправе применить другой executor и собственный аккаунт
с нужными правами. Режим `restore ... --executor connector --bridge DIR` симметричен
backup: агент читает Gmail/Drive, общий движок проверяет и восстанавливает.
