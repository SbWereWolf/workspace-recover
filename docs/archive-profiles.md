# Пользовательские команды упаковки и распаковки

Версия формата: `workspace-recover/archive-profile/v3`. `archiveProfile` нужен только когда автор сознательно выбирает внешний формат/codec. Без него работает штатный TAR.GZ/PAX.

Инструмент **не выбирает архиватор и не поставляет каталог команд для 7z/xz/zip**. Автор задаёт обе команды сам — `pack.argv` и `unpack.argv` — вместе с `cwd`, `env`, `timeoutMs` и `requires.executables` при необходимости. Это сохраняет одну цель продукта: собрать восстановимый пакет и применить его, не превращая recovery tool в менеджер архиваторов.

Минимальный каркас:

```json
{
  "schema": "workspace-recover/archive-profile/v3",
  "kind": "exec",
  "format": "YOUR_FORMAT",
  "requires": {"executables": ["YOUR_TOOL"]},
  "pack": {"argv": ["YOUR_PACK_COMMAND", "...", "${sourceRoot}", "${archivePath}", "${selectionNul}"]},
  "unpack": {"argv": ["YOUR_UNPACK_COMMAND", "...", "${archivePath}", "${targetRoot}"]}
}
```

Это только форма контракта: конкретные команды принадлежат пользователю.

## Контракт

`kind: exec`, `format`, обе команды `pack`/`unpack` и `schema` обязательны.
Команды содержат `argv` как массив строк; допустимы `cwd`, строковый `env`,
положительный `timeoutMs`, стандартный report. Выполнение без implicit shell.
Явный запуск shell-программы автором является его доверенным кодом.

Подстановки: `${sourceRoot}` только pack, `${targetRoot}` только unpack,
`${archivePath}`, `${selectionNul}`, `${workspace}`, `${stepDir}`, `${operation}`.
Они связываются исполнителем, а не запрашиваются как operator inputs. Имена
неизвестных подстановок отклоняются. `requires.executables` проверяет доступность
программ; это не подтверждение версии внешней программы.

`format` определяет расширение и пару декодирования. Встроенный reader читает
только tar.gz; произвольный формат требует явного профиля и inventory. Результат
внешнего unpack сравнивается с inventory по именам, типам, Unix modes, размерам,
SHA256 и целям ссылок **до** авторского workflow. Нулевой код распаковщика сам
по себе не доказывает восстановление. Для tar.gz дополнительно проверяется
архив строгим встроенным reader до внешней распаковки.

## Распаковщик отдельно от payload

Структура `archiveProfile` задаётся прямо в project template/manifest. Отдельный каталог готовых profile-файлов не поставляется: выбор внешней программы и её аргументов принадлежит автору. `bootstrap` объявляет отдельные файлы `{id,path,sha256?}`.
Команда ссылается на `${bootstrap.ID}`. При backup файл копируется в сессию,
проверяется и отправляется отдельно; manifest получателя содержит ID/размер/хеш/mode
вместо локального исходного пути. Restore скачивает и проверяет bootstrap до unpack.
Скрипт, существующий только внутри неоткрытого архива, не может быть bootstrap.

## Безопасность и границы

Произвольная внешняя команда — доверенный авторский код. Она не ограничивается
временной папкой и не наследует защищённые файловые операции встроенного reader.
Поэтому поставляемый exec-контракт использует новый target; для merge сохраняется
встроенный профиль. Symlink target/предки отвергаются при подготовке назначения.
Встроенная защита не отключается ради внешней команды. Произвольный формат не
получает обещания sandbox или безопасной обработки враждебного декодера.

Отказ pack/unpack останавливает восстановление; авторские уведомительные тесты
не запускаются по неполному дереву. Частичные данные сохраняются. Заданный timeout
подаёт TERM, затем KILL через 250 ms, если именно запущенный процесс не завершился.
Это не гарантия управления всеми произвольно отделившимися потомками.

`info SESSION --type pack` и `--type unpack` показывают сохранённые результаты.
`--view full` выводит только путь. Временная успешная комната удаляется по общему
контракту; это не автоматическая очистка последствий авторских тестов.

Формат, команды и bootstrap references сохраняются в одном внешнем recovery
manifest. Обычный restore и backup rehearsal используют один и тот же executor.
