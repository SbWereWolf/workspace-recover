# Версия формата и выпуск приложения

Все собственные самостоятельные JSON-документы имеют поле `schema` текущего
семейства `workspace-recover/<kind>/v3`. Вложенные workflow/actions/reporters
версионируются содержащим их документом; JSON Schema описания имеют `$id` с той
же версией. Данные Google OAuth/API и пользовательские raw JSON/JUnit отчёты
имеют внешние форматы: их нельзя переименовывать заменой `/v1/` на `/v2/`.
Например, Gmail API остаётся `/gmail/v1/`, независимо от формата продукта.

Текущий исполняемый файл не читает `/v1`, неизвестные версии и документы без
обязательной версии. Автоматической миграции и fallback нет. Для старой копии
используется архив соответствующего старого выпуска. Исторический plan остаётся
действительным для создавшего его исполнителя; редактирование исходного manifest
не влияет на этот plan.

`requires.formatVersion` должен совпасть с текущим; неизвестные capability names
отклоняются. Версия программы хранится в `package.json`, выводится через `--version`
и присутствует в `CHANGELOG.md`. Документы и skill входят в поставку.

## Git-политика самостоятельного продукта

В собственном репозитории каждый commit изменяет версию приложения; тема commit
содержит `v<version>`, а сам commit помечается тегом `v<version>`. Перед передачей:

```bash
node scripts/check.mjs
node scripts/release-check.mjs --git
```

Проверка Git требует, чтобы корнем repository была именно папка продукта, tree
был чистым, текущий тег указывал на HEAD, тема содержала версию, а версия отличалась
от первого родителя. Скрипт не выполняет commit/tag/push и не изменяет родительский
репозиторий. В поставке без `.git` обычная проверка работает:

```bash
node scripts/release-check.mjs
```

Она не объявляет Git history проверенной. Наличие файла `CHANGELOG.md` само по себе
не означает, что commit или тег были созданы.

## npm и SemVer после 1.0.0

Начиная с `1.0.0`, npm package является основной моделью распространения между агентами. SemVer — часть продуктового контракта:

- patch — совместимые исправления;
- minor — совместимое расширение существующей цели recovery;
- major — несовместимое изменение CLI/manifest/runtime contract.

Перед релизом обязательны локальные tests/release-check, затем `npm pack`, установка **из полученного `.tgz`** в отдельный prefix и smoke основных CLI-команд. Проверяются именно упакованные байты, а не только исходный checkout. `private:true` запрещён для публичного release package.

Публикация в registry — отдельный внешний факт. Release tarball, Git tag и `publishConfig` означают готовность к публикации, но не заменяют успешный `npm publish` и registry readback.
